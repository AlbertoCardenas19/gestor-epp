# Producto y alcance conocido

## Idea del proyecto
Aplicación web para facilitar el trabajo de una prevencionista de riesgos en una empresa con varios proyectos. Contempla la gestión de EPP y señaléticas, su inventario por proyecto, el proceso de cotización y compra, y la trazabilidad de las entregas hasta los trabajadores. La empresa también necesita gestionar presupuestos y el dinero que ingresa y sale de cada proyecto. [S1, S2]

EPP significa elementos de protección personal.

## Situación actual
No hay un sistema definido para este proceso; la coordinación se realiza principalmente mediante WhatsApp. La prevencionista prepara una lista de necesidades, obtiene cotizaciones y las presenta a su jefe. Cuando él aprueba, ella realiza la compra. Luego entrega los elementos a otra persona, y se necesita conocer a qué trabajadores se entregaron posteriormente. [S1, S2]

## Alcance conversado
- Una empresa con varios proyectos. [S1]
- Uso inicial por la prevencionista, con posibilidad de incorporar más usuarios después. [S1]
- Aplicación web utilizable desde computador y celular. [S1]
- Inventario por proyecto. [S1]
- EPP y señaléticas inicialmente; posibilidad de gestionar otros elementos más adelante. [S2]
- Registro de entregas, devoluciones y reposiciones. [S1]
- Cotizaciones, aprobación del jefe y compra realizada por la prevencionista. [S1, S2]
- Trazabilidad hasta los trabajadores destinatarios de los EPP. [S2]
- Adjuntos de facturas, comprobantes de transferencia y cotizaciones. [S1]
- Presupuestos e ingresos/egresos por proyecto para la empresa. [S1, S2]

Estos puntos describen el alcance conversado; no establecen qué debe entrar primero ni una lista cerrada del MVP.

## Aclaración financiera
La prevencionista no administra dinero. Aunque cada proyecto tiene presupuesto, el usuario aclaró que la gestión presupuestaria y financiera es una necesidad de la empresa. No debe modelarse a la prevencionista como responsable financiera por defecto. [S2]

## Contexto del desarrollo y evolución
El usuario quiere desarrollar este software como su práctica profesional de Analista Programador en INACAP. La idea surgió de su amiga para facilitar su trabajo; se conversó desarrollar el producto comercial junto con ella. No se espera necesariamente que la empresa compre el software completo a precio comercial: el interés es la aceptación formal como estudiante en práctica y, eventualmente, un aporte menor. [S4]

La comercialización futura no define por sí sola un SaaS, múltiples empresas, planes de pago ni condiciones de licencia. No se recuperaron acuerdos que cierren esas decisiones.

## Nivel de definición
El usuario indicó que las reglas de negocio detalladas se verán más adelante durante el desarrollo. No se ha recuperado un alcance de MVP cerrado ni aceptación explícita de un stack. [S3, S6]
